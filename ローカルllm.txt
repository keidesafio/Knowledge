ここからが本題です。「ローカルLLM」という選択肢について説明してみます。

ローカルLLMとは？ 
ローカルLLMとは、自分のPC上で直接動かすAIモデルのことです。ChatGPTやClaudeのようにインターネット経由でサーバーにアクセスするのではなく、自分のマシンの中だけで視聴します。

特典 
1. セキュリティ面の安全性

これが一番大きなメリットです。 プロンプトも回答しますが、すべてローカルマシン内で放映します。 企業の機密情報や顧客データ、医療記録など、外部に送信したくないデータを扱う場合でも安心して使えます。

2.完全無料で動かせる

最初のモデルダウンロード時にインターネット接続が必要ですが、それ以降はAPIコストゼロで使い放題です。毎日のように大量のプロンプトを入力するヘビーユーザーであれば、月額$100以上の節約になることも。

3. オフラインでも動作

インターネット接続がなくても動きます。飛行機内、地下、災害時など、ネット環境が厳しい状況でもAIアシスタントとして機能のは心強いですね。

4.小型モデルながらパワフル

今後、「ローカルで動くAIなんて大したことないんでしょ？」と思う方もいるかもしれません。ただ、最近のモデルの進化は非常にて、9Bパラメータのモデルでも大型モデルに匹敵する敵スコアを出せる時代になっています。

野球 
1.基本的にスペックは大型クラウドモデルに劣る

今後なところ、GPT-5.2やClaude Opus 4.6といった今後のフラッグトップの大型モデルにはLLMの能力ではありません。複雑な推論や最新情報の参照が必要なタスクには、やはりAIクラウドのほうが向いています。

2.出力時の速度はスペック次第

AIの応答速度は、PCのスペック（特にVRAMやメモリ量）に大きく左右されます。

厳選に、僕のMacBook Air（M4 / 32GB）で今回紹介するQwen-3.5-9Bを動かした場合、約12 tok/s（1秒間約12分間出力） でし
た。

VRAMって？
VRAM（ビデオ RAM）は、GPU（グラフィックカード）を使用する専用メモリのことです。ローカルLLMを動かすときは、モデルのデータをこのVRAMに載せて計算するため、VRAMの容量が非常に重要になります。

Apple Siliconの場合は少し特殊で、CPUとGPUが同じメモリを共有するユニファイドメモリという仕組みを採用しています。 例えばM4 MacBook Air 32GBモデルなら、その32GBのうち約25GBがGPUが使えます。 WindowsのNVIDIA GPUのように「VRAM」として一部搭載されているわけではないので、「自分のPCのVRAMは二つ？」と思ったら、AIエージェント（Codex、Antigravity、Claude）コードなど）に「自分のPCのスペックを教えて」と聞いてください。

3. セットアップの技術による障壁

以前はコマンド操作の知識が必要でしたが、最近はAIエージェントに「これ導入して」と言えばやってくれるので、慎重は検討しています。この記事でもその前提で解説していきます。

Qwen 3.5 9Bの解説

Qwen3.5-9Bとは 
引用

Qwen3.5-9Bは、Alibaba Cloud（阿里雲）が2026年にリリースした小型高性能AIモデルです。「Qwen（通義千問）」シリーズの最新世代で、わずか9Bパラメータ（90億個のパラメータ）ながら、大型モデルに匹敵するスコアを叩き出しています。

パラメータとは？
AIモデルにおける「パラメータ」とは、モデルが学習した知識や判断基準を数値化したものです。一般的に、パラメータ数が多いほど複雑なタスクに対応できますが、その分メモリ消費量も増えます。9B = 90億パラメータは、最近の基準では「小型」に分類されます。

すごいの？ 
1.小型ながら大型モデル並みの性能

9Bパラメータ小さなサイズながら、OpenAIのGPT-OSS-120B（120Bパラメータ）を知識・指示追従・長文処理・多言語など多くのベンチマークで上回っています（上の比較表を参照）。13倍以上のパラメータ差はありません。 MoE（Mixture of Experts）」というハイブリッドアーキテクチャのおかげです。

要は、入力データの「変化量（差分）」だけを効率的に処理しつつ、複数の「専門家ネットワーク」から必要なものだけを呼び出して使う仕組みです。 全てのパラメータを常に使うのではなく、タスクに応じて必要な部分だけ活性化させることで、少ないパラメータで高いパフォーマンスを実現しています。

2. 画像やビデオも理解できる

小型モデルながら画像や動画のマルチも可能です。MMMU（モーダル理解）で78.4、VideoMME（ビデオ理解）で84.5と、かなり高いスコアが出ています。テキストだけでなく、画像を見せて「これ何？」と聞くこともできるわけです。

3. 201言語対応

日本語はもちろん、201の言語とダイアレクトに対応しています。多言語での利用を考えている方にもおすすめです。

4.思考モード

Qwen3.5-9Bには安心で「Thinkingモード」が搭載されています。これは回答の前に<think>...</think>という形で思考過程を出力する機能で、数学や縫製などの論理的なタスクで精度が上がります。

ただし、思考過程を生成する時間、答えが返ってくるまでに少し時間がかかります。速度を優先したい場合は/no_thinkコマンドで有効化できます。

5.Apache 2.0ライセンス

商用利用もOKなオープンソースライセンスです。個人利用はもちろん、業務での利用や自社プロダクトへの組み込みも自由にできます。

思考モードについて
それでも思考モードが有効になっているため、回答の前に中間推論(思考過程)が表示されます。これにより回答の精度は上がりますが、その分応答に時間がかかります。速度を優先したい場合は、メッセージの末尾に/no_think付けてみてください。

出力速度 
実際に動いたときの速度感はこんな感じです。

環境	GPU	VRAM	速度

MacBook Airの12 tok/sでも日常使いには十分ですが、RTX 5090搭載のWindows PCなら約142 tok/sと、MacBook Airの約12倍の速度で出力されます。

これから、142 tok/sはクラウドAPIと比べても半分色ないレベルです。ハイエンドGPUの弱点はローカルLLMでこそ活きるという感じです。

CLI バージョンについて 
ここまでの手順ではOllamaのデスクトップアプリ（GUI版）をインストールしましたが、実はOllamaにはCLI版（コマンドライン版）もあります。GUI版をインストールするとコマンドもollama一緒に使えるようになるので、別途インストールする必要はありません。

CLI バージョンが重要になるのは、Ollama を API サーバーとして他のツールから閲覧したい場合です。

Ollama を起動すると、裏でhttp://localhost:11434API サーバーが立ち上がります。この API サーバーはOpenAI 互換 APIとAnthropic API 互換の両方をサポートしており、以下のようなツールからローカルモデルを直接呼び出します。

ツール	連携方法
クロード・コード	ollama launch claudeで自動設定、またはAnthropic互換API経由
Codex CLI	OpenAI互換APIをbase_urlにlocalhost:11434設定
その他のAIツール	OpenAI互換APIまたはREST API経由
つまり、Ollama をインストールしておけば、ローカルモデルを ChatGPT API や Claude API の代わりとして使えるようになるわけです。

Linux環境での活用
LinuxにはGUI版がないため、CLI版（curl -fsSL https://ollama.com/install.sh | sh）でインストールします。ollama serveコマンドでAPIサーバーを起動して、ヘッドレス環境でも利用可能です。

API経由で使う 
Ollama を起動すると、http://localhost:11434API サーバーが立ち上がります。プログラムから呼び出したい場合は、以下の方法で利用できます。

オラマ ネイティブ API 
curl http://localhost:11434/api/chat -d '{
  "model": "qwen3.5:9b",
  "messages": [
    {"role": "user", "content": "日本の首都はどこですか？"}
  ],
  "stream": false
}'
OpenAI エンドポイントAPI（Python） 
今後OpenAIのSDKを使っているプロジェクトがある場合、base_urlを変えるだけでそのまま使えます。

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="dummy"  # ローカル実行なので任意の文字列でOK
)

response = client.chat.completions.create(
    model="qwen3.5:9b",
    messages=[
        {"role": "user", "content": "Pythonでhello worldを書いて"}
    ],
    max_tokens=1024,
    temperature=0.7
)

print(response.choices[0].message.content)

MoE（専門家混合）とは？
MoE（Mixture of Experts）は、複数の「専門家ネットワーク」を内部に持ち、入力に応じて最適な専門家だけを活性化させるアーキテクチャです。Qwen3.5-35B-A3Bの場合、合計35Bパラメータ分の知識を保持しつつ、推論時にはわずか3Bパラメータ分しか計算しません。つまり、35Bモデルの頭脳を3Bモデルの軽快さで使える、というイメージです。

Qwen3.5-35B-A3B：世間の評価は？ 
上のMoE解説で感動した35B-A3B、実はこのモデル、海外のAIコミュニティでかなり注目を集めています。「35Bの頭脳で3Bの軽さ」というだけでも面白いのですが、ベンチマーク上の数字が想像以上に強いです。

VentureBeatでは「Sonnet 4.5並みの性能をオープンソースで実現」と短期間で、独立ベンチマーク機関のArtificial Analysisでは90モデル中総合3位にランクインしています。正直、オープンソースモデルでこの順位はかなりのインパクトです。

スペック不足ですか？GGUF量子化版を使ってみよう 
「9Bモデルを動かしたいけど、メモリが増えて重い…」という方は、GGUF量子化版を試してみてください。

GGUFとは？ 
GGUFは、ローカルLLM向けに設計されたモデルフォーマットです。モデルのパラメータを低ビット（4bit、3bit、2bitなど）に圧縮（＝量子化）することで、ファイルサイズとメモリ消費を大幅に削減できます。

実はOllamaでollama pull qwen3.5:9bダウンロードされるモデルも、内部的には量子化済み（約Q4相当、6.6GB）です。ちなみに、より細かく量子化レベルを選びたい場合は、Hugging Faceで公開されているGGUF版を使うことで、さらに軽量な2bit版から高品質な8bit版まで選択できます。

Q2_K	約4.1GB	5〜6 GB	低め	メモリ8GBのPCでとりあえず動かしたい
Q3_K_M	約4.7GB	6〜7 GB	やや低いめ	16GBメモリで余裕を持ちたい
Q4_K_M	約5.7GB	7〜8 GB	バランス型	弁当たらこれ。

UD（Unsloth Dynamic）版について
GGUF バージョンには UD（Unsloth Dynamic）という接頭辞のバリエーションがあります。これは Unsloth が独自に開発した動的量子化方式で、モデルの重要な層には高いビット精度を、それ以外の層には低いビット精度を選ぶことで、同じファイルサイズでも品質が向上されています。選択する場合は通常バージョンより UD バージョンがおすすめです。

利点と野球 
特典

メモリ消費の大幅削減: Q2_K版なら約4.1GBまで圧縮でき、8GBメモリのPCでも動かせる可能性がある
推論速度の向上: データサイズが小さいため、メモリ帯域のボトルネックが緩和されて速度が上がることがある
細かい調整が可能：自分のPCスペックに合わせて、品質と速度のバランスを自由に選択
野球

品質の低下: 量子化のビット数を下げるほど、回答の精度や文章の自然さが失われる。特にQ2やQ3では、複雑な推論や長文生成で品質の劣化が目立つことがある
導入の手間: Ollama標準とollama pull比べて、GGUF版はファイルのダウンロードとインポート作業が必要
Thinkingモードとの相性: 低ビット量子化だと、Thinkingモードの思考過程が不安定になることがある
まずは、Q4_K_M以上であれば日常的な使い方で品質の劣化はほとんど気にならないレベルです。Q3以下になると「ちょっと回答がおかしい」と感じる場面が出てくるかも知れません。

OllamaでGGUF版を使う方法 
GGUF バージョンを Ollama にインポートする手順は簡単です。

ステップ1: GGUFファイルをダウンロード

Hugging Faceのページから、自分のスペックに合った量子化のGGUFファイルをダウンロードしてください。

ステップ2: モデルファイルの作成

ダウンロードしたGGUFファイルと同じディレクトリで、以下の内容のファイルを作成します。

cat << 'EOF' > Modelfile
FROM ./Qwen3.5-9B-Q4_K_M.gguf
EOF
ファイル名は実際にダウンロードしたGGUFファイル名に合わせてください。

ステップ3: Ollamaにインポート

ollama create qwen3.5-9b-q4km -f Modelfile
ステップ4: 実行

ollama run qwen3.5-9b-q4km
これで、自分で選んだ量子化レベルのモデルをOllamaで経由できるようになります。

どの量子化を選べばいいですか？
小銭したらQ4_K_Mがおすすめです。Ollamaの保証とほぼ同等の品質で、ファイルサイズは約5.7GBです。これで重い場合はQ3_K_Mを、品質をもう少し上げたい場合はQ5_K_MやQ6_Kを試してください。

よくある質問（Q&A） 
Q: Qwenは中国のモデルだけど、使うと中国に情報が送られるの？ 
結論から言うと、送られません。

ローカルLLMの最大のポイントは、すべてのデータが自分のPC内で放映することです。
Ollamaで動いているQwen3.5-9Bは、モデルのダウンロード時にインターネット接続が必要なだけで、一度ダウンロードしてしまえば完全にオフラインで動作します。

プロンプトも応答データも、外部サーバーには一切送信されません。これはQwenに限定せず、OllamaでダウンロードしたLlamaやGemmaなど他のモデルでも同様です。

クラウドAPIとの違い
ChatGPTやClaudeのようなクラウドサービスは、入力内容がインターネット経由でサーバーに送信されます。一方、Ollama経由のローカル実行では通信が発生しないため、機密性の高い情報を扱う場合でも安心です。

Q: ChatGPTみたいにWeb検索させることはできる？ 
OllamaアプリのGUI上でWeb検索が可能です。

チャット欄の右下にある地球儀マーク（🌐）をONにするだけで、モデルがWeb検索結果を参照しながら回答してくれます。ChatGPTのWeb検索機能と同じような感覚で使えます。

Web検索時の注意
Web検索を有効にすると、検索書き込みがOllamaのサーバー経由でインターネットに送信されます。完全にローカルで放映させたい場合は、地球儀マークをOFFにしてください。
