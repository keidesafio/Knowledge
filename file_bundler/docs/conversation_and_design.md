# 会話から実装までの記録

日付：2026-10-12（日本時間）。このテーマの会話を、要件・設計・実装・検証に整理した記録です。逐語録ではありません。対象は今回のバンドル化に関するやり取りのみです。

## 1. 最初の相談

大量のローカルファイルがあり、拡張子はばらばら。最終的に3ファイル以内へまとめたい。ただし、全文だけでなく画像・表・図の情報も落としたくない。

既に試した方式は、文字をJSONへ、各ファイルの見た目をPDFへ入れるもの。ExcelをPDFに入れたところ、見切れが起きた。

この相談に対して、原本・構造・見た目を別の表現で保持する案を提示した。

| 出力 | 目的 |
|---|---|
| originals.zip | フォルダ構成と元ファイルのバイト列を保持 |
| content.json | 全文、表やセルの構造、数式、出典、PDF対応、抽出結果を保持 |
| visuals.pdf | 配置・色・図・画像などの視覚情報を保持 |

保存の完全性と、読み込み先のAIがすべて読めることは別。原本があれば取りこぼしの再抽出ができるが、ZIPを読めないAIにJSON/PDFだけを渡しても、原本の全情報が伝わることにはならない。

## 2. ローカルで何をすればよいか

ユーザーは次に、ローカル保存されたファイル群に具体的に何をすればよいかを質問した。

処理の流れとして以下を提示した。

1. サブフォルダを含めてファイルを列挙し、ID・相対パス・形式・サイズ・ハッシュ・処理状態を記録。
2. 原本を変更せずZIPへ格納。
3. 形式ごとに構造抽出と見た目の変換を別々に実施。
4. Excelは全シートと内容範囲を調べ、セル情報を抽出してから全体図・詳細図を作る。
5. JSONとPDFをファイルID・ページ番号等で結び付ける。
6. ハッシュ、処理対象数、対応範囲、警告、表示を検証する。

ファイル形式別の理想的な抽出対象：文書の本文・見出し・表・脚注・コメント、Excelのセル座標・値・表示文字列・数式・保存済み結果・結合・非表示状態、スライドのノート・図形位置、画像や図の元の位置・OCR・接続情報等。

図のAI説明文だけで画像を置き換えない。説明を付けるなら生成した説明と原文を区別する。外部参照先のデータは元ファイル内にないことがあるため、必要なら別途収集する。

## 3. Excelの見切れ対策として検討した内容

- 全体図と、文字が読める大きさの詳細図を併用する。
- 既存の印刷範囲だけに頼らない。
- 縦横へ分割し、境界を少し重複させる。
- 各ページへ出典・シート・範囲などを表示する。
- 理想的には見出し行・識別列を繰り返す。
- 理想的には結合セルや図形を考慮して分割境界を調整する。
- 長文セルは全文をJSONにも保存する。
- 原本の表示状態を記録し、非表示の情報も抽出対象とする。

## 4. 実行ファイル作成の依頼と採用した実装

ユーザーは「自分が手順を実行すれば実現できるコマンドなりPythonファイル」を要求した。OSやOfficeの有無への回答はまだなかったため、Windows/macOS/Linux向けPython CLIとLibreOfficeを採用した。

| 項目 | 実装状態 |
|---|---|
| 3ファイルへの出力 | 実装済み |
| 原本バイト列・相対パスの保存とSHA-256照合 | 実装済み |
| JSONとPDFの出典対応 | 実装済み |
| Excelの全体図・重複付き詳細分割 | LibreOffice SinglePageSheetsとPDF座標分割で実装 |
| XLSX/XLSMのセル全文・数式・保存済み計算結果 | 実装済み。共有式等は元XMLの属性を保持し、展開しない |
| 長文セルの補助表示 | 全セルを折り返し・改ページしてPDF掲載 |
| Office内部の表・図・ノート等の構造 | XMLと関連ファイルの参照関係をJSONに保持。共通意味モデルへの完全な正規化は未実装 |
| 書式を適用した表示文字列 | セルJSONには未実装。値・スタイル参照とPDFを参照 |
| 見出し行・識別列の繰り返し | 未実装 |
| セル・図形の境界に合わせた分割 | 未実装。24ポイントの重なりで補助 |
| 全グラフの個別ページ化 | 未実装。シート全体表示に含める。対応する埋込ビットマップは個別表示 |
| 非表示シート | 全体表示とセル抽出の対象 |
| 非表示行列 | XLSX/XLSMのセル値は抽出。図上で必ず展開される保証はない |
| OCR | Tesseractを別途導入して --ocr を指定すれば実行。誤認識・失敗はありうる |
| 旧Excelの詳細セル抽出 | 未実装。LibreOfficeの表示変換が中心 |
| 不明な形式 | 原本保存とarchive_onlyの記録 |
| 表示の完全性の自動証明 | 未実装。人による確認が必要 |

元のOfficeファイルを変更せず、一時コピーから変換。出力フォルダは入力フォルダ外に限定し、既存の出力先へ上書きしない。原本の読み取り中の変更を検出すると止める。完了前は最終出力ディレクトリを公開しない。

## 5. 動作確認

Linux環境で次の自作サンプルを使った。実際のユーザー資料はまだ受領しておらず、その資料での検証はしていない。

- 日本語テキスト：長い本文。
- PNG：四辺を持つ1600×1000画像。
- XLSX：印刷範囲A1に対しZ1にも値、長文セル、保存済み結果付き数式、非表示シート。
- 不明拡張子のバイナリ：未対応として保存されることの確認。

確認済み：4ファイルの原本ハッシュ一致、非表示シートのJSON保持、長文セル末尾の保持、数式A2*2の保持、右端値と非表示シート値のPDFへの掲載、分割範囲の右端・下端までの到達、既存出力先の拒否、補助PDFの日本語長文の目視確認。

生成されたサンプルPDFは21ページ。元のバイナリはarchive_onlyとして記録されたため終了コード2。これは意図した動作。PDFのページ数は将来のエンジン・フォント差で変わりうるため固定の保証値ではない。

OCR、Windows/macOS、すべてのOffice形式、グラフの完全再現、非常に巨大な実資料での実行は未検証。
